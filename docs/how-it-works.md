## ภาพรวม

│  Watcher (รอบตรวจ)                                                           │

| `refs/` | ภาพอ้างอิงตอนน้ำแห้ง (ไม่ถูกลบอัตโนมัติ) |

## Claude ได้รับอะไร และตอบอะไร

**คำขอ 1 ครั้งต่อรอบ** (ทุกกล้องในครั้งเดียว):

1. System prompt คงที่ — บทบาท “น้องฝน” วิธีอ่านเส้น วิธีแยก *พื้นเปียก/แสงสะท้อน* ออกจาก *น้ำขังจริง* และข้อควรระวังภาพอินฟราเรด
2. ข้อมูลบ้าน + รายชื่อกล้อง (มีเส้นอะไร โน้ตของเจ้าของ) + **ภาพอ้างอิงตอนแห้ง**
3. ภาพปัจจุบันของแต่ละกล้อง (วาดเส้นแล้ว) พร้อมเวลาและบอกว่าเป็นภาพอินฟราเรดหรือไม่

ส่วนที่ 1–2 แทบไม่เปลี่ยน จึงใช้ **prompt caching** (TTL 1 ชั่วโมงเมื่อรอบตรวจห่างเกิน 5 นาที) — จ่ายส่วนนี้แค่ ~10% ในรอบถัด ๆ ไป

**คำตอบ** ถูกบังคับรูปแบบด้วย structured outputs (JSON schema):

```json
{
  "cameras": [
    { "id": "cam2", "line_status": "at_red", "water": "flooded", "coverage_pct": 64, "note_th": "ขอบน้ำถึงเส้นแดงหน้าบันไดแล้ว" }
  ],
  "level": 100,
  "level_status": "critical",
  "distance_th": "ถึงเส้นแดงแล้ว",
  "confidence": 0.82,
  "headline_th": "น้ำถึงเส้นแดงในโรงรถแล้ว"
}
```

- `line_status`: `no_lines` · `below_yellow` · `at_yellow` · `at_red` · `cannot_tell`
- `level`: 0 = แห้ง · ~25 = มีน้ำแต่ยังห่างเส้น · 50 = เส้นเหลือง · 100 = เส้นแดง
- `level_status`: ความเห็นรวมของ AI เอง — ถ้าเป็น `unknown` (มองอะไรไม่ออกเลย) ระบบจะถือว่า **ไม่รู้ระดับ** ไม่ใช่ "แห้ง" (เหมือน `level_status` ของต้นทาง)
- `coverage_pct`: สัดส่วนพื้นที่ที่มองเห็นซึ่งมีน้ำขัง ใช้วาดเส้นประในกราฟ (เหมือน `water_coverage_pct` ของต้นทาง)
- `distance_th`: ห่างเส้นแดงเท่าไร (เหมือน `distance_to_critical` ของต้นทาง)
- ตัวเลขที่แสดงบนถังวัดน้ำและกราฟถูก "ปรับให้ตรงกับเส้น": ถ้ากล้องเห็นน้ำถึงเส้นเหลือง ระดับจะไม่ต่ำกว่า 50 และถึงเส้นแดงจะเป็น 100 (ไม่เคยปรับลง) ตัวเลขดิบของ AI เก็บไว้ใน `levelRaw`

ค่าเริ่มต้นใช้ `claude-sonnet-5` เหมือนต้นทาง (NamMaLaew ใช้ sonnet) ความละเอียดการคิด `medium` (ปรับได้) ถ้าเลือกตระกูล Opus จะเปิด server-side fallback ไว้ด้วย โมเดลปฏิเสธคำขอเมื่อไหร่จะลองโมเดลสำรองที่ Anthropic แนะนำให้อัตโนมัติ

### โหมด Claude Code (`AI_ENGINE=claude-code`)

ใช้แพ็กเกจ Claude Pro/Max แทน API key: น้องฝนเรียก

```
claude -p --input-format stream-json --output-format stream-json --verbose \
  --json-schema <schema> --system-prompt <prompt> --tools "" --no-session-persistence --model <model>
```

ส่งภาพเป็น content block ทาง stdin แล้วอ่านผลจาก `structured_output` ของ event `result` — ไม่เปิดเครื่องมือใด ๆ ให้ Claude (อ่านไฟล์/รันคำสั่งไม่ได้)

## ตัดสินสถานะ (src/judge.js)

เส้นที่เจ้าของบ้านขีดคือคำจำกัดความของ “น่าห่วง” และ “อันตราย” จึงชนะตัวเลข `level` เสมอ ลำดับกติกาตามต้นทาง NamMaLaew (`derive_final_status`) และเลือกทางที่ปลอดภัยกว่าในจุดที่ต่างกัน:

1. ดึงภาพไม่ได้เลย หรือ AI ตอบไม่ได้ → **มองไม่ชัด**
2. กล้องไหนบอก `at_red` → **อันตราย** (ชนะเสมอ แม้กล้องตัดสินอีกตัวจะดึงภาพไม่ได้ — ต้นทางจะตอบ "ไม่รู้" ในกรณีนี้ เราเลือกปลุกไว้ก่อน)
3. **ยังไม่มีเส้นแดงเลยสักกล้อง** (ไม่มีเส้นเลย หรือมีแค่เส้นเหลือง) และ `level` ≥ เกณฑ์อันตราย (90) → **อันตราย** — ถ้ามีเส้นแดงแล้ว ตัวเลขอย่างเดียวขึ้นได้สูงสุดแค่เฝ้าระวัง (กติกาเดียวกับต้นทาง)
4. กล้องไหนบอก `at_yellow` หรือ `level` ≥ เกณฑ์เตือน (50) → เหตุผลของ **เฝ้าระวัง**
5. “กล้องตัดสิน” (กล้องที่มีเส้นแดง หรือถ้าไม่มี ใช้กล้องที่มีเส้นเหลือง) ตัวไหนดึงภาพไม่ได้/มองไม่เห็นขอบน้ำ → **มองไม่ชัด** (แต่ถ้าข้อ 4 เจออะไรแล้ว → เฝ้าระวัง)
6. ยังไม่มีเส้นเลย และ AI บอกว่ามองไม่ออก (`level_status: unknown`) → **มองไม่ชัด** (ไม่ใช่ "ปกติ")
7. ปกติ แต่ **แนวโน้ม** ขึ้นเร็ว (≥ 8/ชม.) และคาดว่าจะถึงเส้นแดงภายใน 60 นาที → **เฝ้าระวัง (เตือนล่วงหน้า)**

คำตอบของ AI ถูกตรวจกับเส้นที่มีจริงด้วย เช่น AI บอกถึงเส้นแดงในกล้องที่ไม่มีเส้นแดง → ลดเป็นเส้นเหลือง

**แนวโน้ม** = ความชันแบบ least squares ของ `level` ในชั่วโมงล่าสุด (ต้องมีอย่างน้อย 3 ผลที่ห่างกัน ≥ 12 นาที)

## นโยบายแจ้งเตือน (src/alerts.js)

| เหตุการณ์ | ทำอะไร |
|---|---|
| เห็นเส้นแดงครั้งแรก | บันทึกว่า “รอยืนยัน” แล้ว **ตรวจซ้ำ** หลัง 90 วินาที (ยังไม่ปลุก) |
| ตรวจซ้ำยังแดง | ส่งข้อความ + รูป + ปุ่ม และเปิดไซเรน · เตือนซ้ำทุก 10 นาทีระหว่างที่ยังแดง |
| ตรวจซ้ำไม่แดง | ยกเลิกเงียบ ๆ (บันทึกไว้ในประวัติ) |
| ตรวจซ้ำมองไม่ชัด | ยังรอยืนยัน และขอดูอีกรอบ (ไม่เกิน 3 รอบ) |
| เริ่มถึงเส้นเหลือง / น้ำขึ้นเร็ว | ส่งข้อความครั้งเดียวตอนเริ่ม (ไซเรนเฉพาะถ้าตั้งให้ดังตั้งแต่เส้นเหลือง) |
| แดง → เหลือง | บอกว่าน้ำลดลงต่ำกว่าเส้นแดงแล้ว + ปิดไซเรน |
| กลับสู่ปกติ | ข้อความ “น้ำลดแล้ว” + ปิดไซเรน + ยกเลิกงดเสียง |
| มองไม่ชัดติดกัน 3 รอบ | ส่งครั้งเดียว และส่งอีกครั้งเมื่อกลับมามองเห็น |
| กล้องบางตัวดึงภาพไม่ได้ 3 รอบ | ส่งครั้งเดียวต่อกล้อง และเมื่อกล้องกลับมา |

**งดเสียงมี 2 แบบ** — ทั้งคู่ปิดเฉพาะไซเรน ข้อความยังส่งตามปกติ

- **งดเสียงจนกว่าน้ำจะลด** (เหมือน “MUTE UNTIL WATER DROPS” ของต้นทาง): จำระดับตอนกดไว้ (เฝ้าระวังหรืออันตราย) แล้วเปิดเสียงคืนเองเมื่อผลตรวจลดต่ำกว่าระดับนั้น — กดตอนน้ำอยู่ที่เส้นเหลืองนาน ๆ จะไม่ถูกยกเลิกด้วยผลเส้นเหลืองรอบถัดไป · ผล “มองไม่ชัด” ไม่นับว่าน้ำลด
- **งดชั่วคราว N นาที**: หมดเวลาแล้วเปิดเสียงคืน และยกเลิกเองเมื่อกลับสู่ปกติ

ทั้งสองแบบยกเลิกเองเมื่อน้ำกลับสู่ปกติ — กันกรณีงดเสียงไว้แล้วน้ำกลับมาขึ้นอีกโดยไม่มีใครรู้

## ดูกล้องสด (src/camera/live.js)

หน้า **ดูกล้อง** และปุ่ม ▶︎ บนภาพกล้องทุกจุด เปิดภาพสดแบบ MJPEG ผ่านเซิร์ฟเวอร์ของน้องฝนเอง (เบราว์เซอร์ไม่ต้องเข้าถึงกล้องตรง ๆ และรหัสผ่านกล้องไม่เคยถูกส่งไปหน้าเว็บ)

| ลิงก์กล้อง | ภาพสดมาจาก |
|---|---|
| `rtsp://…`, `ffmpeg:…` | ffmpeg แปลงเป็น JPEG ~4 ภาพ/วินาที กว้าง 960px |
| go2rtc `…/api/frame.jpeg?src=…` | สตรีม `…/api/stream.mjpeg?src=…` ของ go2rtc (ลื่นที่สุด) |
| ภาพนิ่ง HTTP / MJPEG / โฟลเดอร์ | ดึงภาพทุก 1 วินาที (หรือต่อสตรีม MJPEG ค้างไว้) |

- ใช้แหล่งภาพเดียวต่อกล้องไม่ว่าจะเปิดดูกี่จอ เริ่มเมื่อมีคนดู และหยุดเอง 8 วินาทีหลังคนสุดท้ายปิด
- ดูสดได้พร้อมกันสูงสุด 4 กล้อง และครั้งละ 15 นาที (กันแท็บที่ลืมเปิดทิ้งไว้ทำให้เครื่องทำงานหนักทั้งคืน)
- ภาพสดหลุดกลางทาง หน้าเว็บรู้เองภายใน ~5 วินาที แล้วกลับไปแสดงภาพล่าสุดพร้อมบอกสาเหตุ

## ฝนรอบบ้าน (src/rain.js)

ตามต้นทาง: แผนที่ OpenStreetMap + เรดาร์ฝนย้อนหลัง ~2 ชม. จาก RainViewer และพยากรณ์ +1/+2/+3 ชม. จาก Open-Meteo บนตาราง 5 × 5 จุดรอบบ้าน (รัศมี 10/25/50 กม.) เซิร์ฟเวอร์เก็บผลพยากรณ์ไว้ 30 นาทีต่อรัศมี (1 ครั้ง = 25 จุดของโควตาฟรี Open-Meteo 10,000 จุด/วัน)

## ความปลอดภัย

- หน้าเว็บต้องล็อกอิน (คุกกี้ HttpOnly + SameSite=Lax ลงลายเซ็น HMAC · เปลี่ยนรหัสผ่านแล้วทุกเครื่องหลุด) · จำกัดการเดารหัส 8 ครั้ง/5 นาที
- คำสั่งที่เปลี่ยนแปลงระบบต้องเป็น JSON จาก origin เดียวกัน · มี Content-Security-Policy · ชื่อไฟล์ภาพถูกตรวจรูปแบบก่อนเปิด
- ค่าลับอยู่ใน `.env` เท่านั้น ไม่ถูกส่งออกทาง API และถูกปิดบังใน log (รวมรหัสผ่านในลิงก์กล้อง)
- บอท Telegram รับคำสั่งจากแชทที่ผูกไว้เท่านั้น
